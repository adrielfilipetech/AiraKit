Initial setup

For this guide, it will be assumed that the file and directory structure remains exactly as it was when the `.zip` file was extracted. However, feel free to reorganize the project as needed, but be mindful of the file paths. If you haven't already, download AiraKit.

Then, copy the `components/` and `static/` directories into the root of your project. The root of your project should look something like this:

📁 components/
├── 📄 footer.html
└── 📄 navbar.html
📁 static/
├── 📁 css/
├── 📁 base/
├── 📄 base.css
├── 📄 layout.css
└── 📄 tokens.css
└── 📁 components/
└── 📄 components.css
├── 📁 fonts/
├── 📁 icons/
├── 📁 img/
└── 📁 js/
├── 📄 components.js
├── 📄 main.js
└── 📄 toast.js


Correcting file paths

First of all, some AiraKit files rely on specific file paths to function correctly, specifically main.js and base.css.

If these paths are not correctly defined, some features may not work as expected. You will have to make a few changes inside these two files.

main.js:

fetch('/AiraKit/components/navbar.html') -> fetch('/components/navbar.html')

fetch('/AiraKit/components/footer.html') -> fetch('/components/footer.html')


base.css:

src: url('/AiraKit/static/fonts/Inter/Inter-VariableFont_opsz,wght.ttf') format('truetype');

Change it to:

src: url('/static/fonts/Inter/Inter-VariableFont_opsz,wght.ttf') format('truetype');


Explanation

“Why not provide AiraKit with the correct paths from the start?”

I tried to do that. However, since AiraKit is hosted at `https://adrielfilipetech.github.io/AiraKit/`, the browser would try to resolve an absolute path without including `/AiraKit/`.

`https://adrielfilipetech.github.io/components/navbar.html` ❌

`https://adrielfilipetech.github.io/AiraKit/components/navbar.html` ✅

As a result, it would not find the file.

“Couldn’t you have used a relative path instead, such as `fetch('components/navbar.html')`?”

If I had kept all the HTML pages in the root directory, yes. However, i did not, which creates the same problem again. In any case, I would still need to include a section covering the files that rely on specific paths and explaining how those paths work. This also gives me an opportunity to explain how to make these changes correctly when adapting AiraKit to your own project.



Main files

3 core files

Every project that uses AiraKit — regardless of framework — must always load these three files, in this order:

tokens.css -> base.css -> main.js

Put these three files inside of your project, then link them inside the html <head> tag, like this:

index.html — <head> 

                                </head>
                                <link rel="stylesheet" href="/static/css/base/tokens.css">
                                <link rel="stylesheet" href="/static/css/base/base.css">
                                <script src="/static/js/main.js" defer></script>
                                </head>

Tokens.css: Color scheme, spacing, radii and typography for the whole kit and every component.

Base.css: Reset, base typography and the base HTML structure (content grid, flex utilities, spacing helpers). Depends on tokens.css.

Main.js: Defines and switches the theme (light/dark), and injects the <aira-navbar> / <aira-footer> web components.

You will also find a file called "layout.css". You can skip it, it defines css for the AiraKit website.


Base HTML structure

navbar · main · footer

AiraKit provides a base HTML structure that includes a navbar, a main body and a footer. All of them should be used inside the <body> tag.

The <main> tag should always be present, while the navbar and footer are optional, since the <main> tag with .main-cont attribute always stretches to fill whatever space is left.

index.html — <body> 

                                <body>
                                <aira-navbar></aira-navbar>

                                <main class="main-cont">
                                <!-- page content -->
                                </main>

                                <aira-footer></aira-footer>
                                </body>

<aira-navbar>: Injected by main.js. Fixed at the top of the page, holds the logo, the theme toggle and the nav links.

<main class="main-cont">: Wraps the page's actual content. Grows to fill the remaining vertical space (flex: 1), pushing the footer to the bottom on short pages.

<aira-footer>: Injected by main.js. Sits at the bottom of the page with links and credits.


Using CSS tags

base.css

All the utility classes live in base.css (which depends on tokens.css). Add them straight to any HTML tag and combine as many as you need — there is no extra CSS to write.

Spacing classes follow the same scale everywhere: 1 = 3rem, 2 = 2rem and 3 = 1rem. So .p1 is the biggest padding and .p3 the smallest.

Using components

To use the basic components always include components.css file.

Also make sure to include components.js when using accordions, carrousel, checkboxes, toggle buttons. Include toast.js for the toasts.

                                </head>

Carousel

1 variant

Use the ids exactly as shown — carousel-demo and carousel-demo-dots — and leave the dots container empty; the dots are added automatically. Only one carousel per page is supported. Arrows and dragging/swiping work right out of the box. File components.js required.

01

Drag or use the arrows to navigate between slides.

02

Works with any content — images, cards, text.

03

Dots update automatically as you navigate.

example 
<div class="carousel" id="carousel-demo">
                                <div class="carousel-track">
                                <div class="carousel-slide"><div class="carousel-slide-inner">
                                <span class="carousel-slide-num">01</span>

                                </div></div>
                                <!-- repeat .carousel-slide for each slide -->
                                </div>

                                aria-label="Previous">...</button>

Toast

4 variants

Add the first div as shown below. It can be anywhere in the file (inside the </main> tag will do). Then add a button with the onClick method showToastKit(message, variant).

Important note: The `toast-kit` class is used for styling, while the `toast-kit` ID is used by `toast.js` to locate the div.

example 
<!-- once per page -->
                                <div class="toast-kit" id="toast-kit" role="status"
                                aria-live="polite"></div>

                                <!-- anywhere in your JS -->
                                <button class="btn_out" onclick="showToastKit('Action completed!', 'success')">
                                Save
                                </button>
